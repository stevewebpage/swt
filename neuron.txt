BOARD RENDERING BUG — ROOT CAUSE FOUND AND FIXED (both submission paths):

BACKSTORY: Earlier session (the "grasping at straws" marathon) had disabled RLS on Posts

ACTUAL ROOT CAUSE: Posts table sorts by sort_order ascending. Neither submit.html nor
admin.html's "Add Post" form ever set a sort_order value on insert — every new post landed
with sort_order = NULL. index.html's loadPosts() fetch (?order=sort_order.asc,created_at.desc)
choked silently on this — no JS error thrown, fetch returned 200, but the board's render
logic never displayed the new rows. Writes always succeeded (confirmed via live $10
Advanced purchase test, post id 83), reads silently failed. This is why "neuron couldn't
find it" in the prior session — there was no error to find, just a silent data gap.

FIX APPLIED to both files: before inserting a new post, fetch current lowest sort_order
(?select=sort_order&order=sort_order.asc&limit=1), subtract 1, use that as the new post's
sort_order. New posts always take the front-of-line spot. Falls back to 0 if the lookup
fails for any reason.
